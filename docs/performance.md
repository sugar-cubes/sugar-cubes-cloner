# Performance

## Generated copiers

A class copied by its fields gets a generated copier the first time it is copied: a class which reads and writes the
fields directly, without reflection and without a loop over field adapters. Final fields are written by method handles
(JDK 16+) or by the toolset. The copiers are generated by the ClassFile API on JDK 24+ and by
[ASM](https://asm.ow2.io) on older JDKs, if ASM is on the classpath:

```xml
<dependency>
    <groupId>org.ow2.asm</groupId>
    <artifactId>asm</artifactId>
    <version>9.11.1</version>
</dependency>
```

Generated copiers are enabled by default and shared by the cloners with the same field policies; classes which cannot
get one (e.g. JDK classes, or classes whose class loader does not see the cloner) are copied as usual.
`Cloners.builder().generatedCopiers(false)` disables them.

In the benchmark of the project (a list of 1000 orders with 10 lines each, JDK 17 and 25) a clone takes 1.2-1.4 ms
with generated copiers, 1.4-1.6 ms by fields with `Unsafe` field access and 1.9-2.3 ms by fields with reflection.

## Copy constructors

The [build tools](build-tools.md) add copy constructors to the classes you list. Such a class is cloned by `new`: final
fields are written directly, no allocator is needed. They are used when the field policy copies all fields of the
class by default; `Cloners.builder().copyConstructors(false)` disables them.

## Tips

- Build a cloner once and reuse it: its caches of copiers live as long as the cloner.
- Prefer type and field actions to object actions and object policies, which are asked for every object.
- Share what does not need copying: `CopyAction.ORIGINAL` for types of immutable values the cloner does not know,
  `singleton()` for well-known instances.
- The parallel mode pays off only for large graphs.
